1Getting started

Four steps take you from an empty account to a working integration.

  1. An administrator assigns a phone number to you. The platform creates an extension on that number, its SIP credentials, and the default call flow in one step.
  2. Open Devices & SIP, press Credentials on the extension, and enter the values into a phone or softphone.
  3. Decide what rings in Call Routing → Call flows. A number's flow decides who answers its incoming calls. A number without a flow rings the extension in its incoming setting.
  4. Create an API key in APIs & Webhooks and add a webhook endpoint for your CRM.
Programmatic accessCreate a key with the scopes your software needs, copy it once, and store it in your CRM's secret store. It is shown a single time.
Event feedbackAdd an endpoint URL, subscribe to the events you care about, and verify the signature on every delivery.

2Authentication & scopes

Every call to /api/v1/* carries a bearer credential:

# a scoped API key (preferred)
Authorization: Bearer eip_<secret>

Keys are generated with cryptographic randomness, stored only as a SHA-256 hash, record when they were last used, and can be revoked at any moment. A revoked key stops working immediately. Endpoints answer 401 for a missing or invalid credential and 403 when the key lacks the scope.

ScopeAllows
calls:readList, read and search calls.
calls:writeStart an outbound call, hang up, or set a disposition.
config:readRead your extensions, your numbers and the provider list.
recordings:readList recordings and stream finalized audio.
voicemail:readList mailboxes and messages, and stream voicemail audio.
voicemail:writeMark an inbox message read, or delete a message.
webhooks:manageList, create, delete and test webhook endpoints through the API.
*Full access. Use it only for trusted administrative tooling.
A key authenticates a server. Never put it in browser JavaScript, a mobile app, or a public HTML audio element: your backend should call us and proxy what the browser needs.

3Place and track a call

POST /api/v1/calls

{
  "phone": "+16235551234",
  "extension": "101@+13025550001",
  "caller_id_number": "+13025550001",
  "contact_id": "582",
  "member_id": "37"
}
FieldRequiredMeaning
phoneYesThe customer to call, in E.164 form (+, country code, number).
extensionNoWhich extension rings first. Send its key (101@+13025550001), or bare digits when that is unambiguous (see below). Defaults to your default outbound extension.
caller_id_numberNoThe number presented to the customer. It must be one of your active numbers. Defaults to the number the extension belongs to.
contact_id, member_idNoYour own identifiers, stored on the call and echoed in every event.

The call is employee-first: the extension rings, and only when it answers does the platform dial the customer and bridge the two legs. No answer means the customer is never called. A successful request returns 201 with the call object.

Which extension is meant

Extensions are numbered per phone number from 101. A three-digit extension is resolved only within the current phone number. The same 101 can exist on two of your numbers, so the API never guesses:

  • Send the key (101@+13025550001) to name one extension exactly. GET /api/v1/extensions lists every key.
  • Bare digits ("extension": "101") work only while exactly one of your extensions carries them. Otherwise the request fails with 400 and asks you to name the phone number too.
  • Digits outside 101–999 are refused with 400.

Idempotency

Send a unique Idempotency-Key header (8–128 letters, digits, . _ : or -) for every user click or job. A replay of a completed request returns 200 with the original call and "idempotent_replay": true; a duplicate that is still in flight returns 409. This is what stops a network retry from placing a second paid call.

# start a call and keep the identifier
curl -sS -X POST {{API_BASE}}/api/v1/calls \
  -H "Authorization: Bearer $EIP_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"phone":"+16235551234","extension":"101@+13025550001"}'

Following one call

EndpointPurpose
GET /api/v1/calls/<call_id>Current state of one call.
GET /api/v1/callsSearch and page through call history. Query: limit (1–100, default 50), offset, extension, status, q. Returns calls, total, limit, offset.
POST /api/v1/calls/<call_id>/hangupEnd an active call. An answered call ends as call.completed, an unanswered one as call.failed; both carry reason: "hangup_requested".
POST /api/v1/calls/<call_id>/dispositionStore your CRM outcome: disposition (up to 100 characters) and notes (up to 2,000). Emits call.disposition.

Treat call_id as the stable identifier and make your own processing idempotent on it.

Browser calls (optional)

POST /api/v1/browser/call takes the same body as POST /api/v1/calls and returns 201 with the call. It exists only when the administrator enables the browser call API; otherwise it answers 404. Use POST /api/v1/calls unless your deployment says otherwise.

5Recordings & voicemail

A call is recorded only when both switches are on: the platform's recording switch set by the administrator, and the extension's own Record switch under Extensions → Edit. Turning either one off stops new recordings.

Recordings

EndpointPurpose
GET /api/v1/recordingsCalls that have recording metadata: {"recordings": [...]}.
GET /api/v1/recordings/<call_id>/fileStreams a recording whose status is finalized or available. Supports Range requests for seeking. Anything else answers 404.

Voicemail

Voicemail is number-scoped. Each extension has one mailbox per line, named <digits>-<number digits>: the 101 on +13025550001 is 101-13025550001, and the 101 on another line is a separate mailbox. Folders are inbox, old and urgent.

EndpointPurpose
GET /api/v1/voicemail/mailboxesYour voicemail mailboxes with the count of new, old, urgent and total messages in each.
GET /api/v1/voicemailsMessages: {"voicemails": [...], "total"}. Filter with extension (a key, a mailbox name, or unambiguous digits) and folder. Each message has id, mailbox, folder, message, caller_id, received_at, format and size_bytes.
GET /api/v1/voicemails/<mailbox>/<folder>/<message>/fileStreams the audio. Supports conditional and range requests.
POST /api/v1/voicemails/<mailbox>/<folder>/<message>/readMarks an inbox message read by moving it to old. Other folders answer 404.
DELETE /api/v1/voicemails/<mailbox>/<folder>/<message>Deletes one message.

Use the message and mailbox fields from the list in the paths above. Proxy audio through your backend so the key never reaches a browser.

6Webhooks & signatures

Add an endpoint in APIs & Webhooks → Add endpoint, or through the API. Each endpoint has a URL (HTTP or HTTPS, without credentials in the address), the signing secret you choose, and the events it wants. Every delivery carries the secret as a bearer token and as an HMAC signature of the exact bytes sent: 

POST /your-endpoint HTTP/1.1
Content-Type: application/json
User-Agent: EngineerIP-Telephony/1.0
Authorization: Bearer <your webhook secret>
X-EngineerIP-Delivery: 8f1c…-unique-id
X-EngineerIP-Timestamp: 1758554400
X-EngineerIP-Signature: sha256=<hex>

{"event":"call.completed","call":{ … },"reason":"hangup_requested"}

Verify it like this — with the raw body, before any JSON parsing:

// Node
const timestamp = req.headers['x-engineerip-timestamp'];
const received  = req.headers['x-engineerip-signature'].replace('sha256=', '');
const expected  = crypto
  .createHmac('sha256', secret)
  .update(timestamp + '.' + rawBody)
  .digest('hex');
const ok = expected.length === received.length &&
  crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(received));

# Python
received = headers["X-EngineerIP-Signature"].removeprefix("sha256=")
expected = hmac.new(secret.encode(), timestamp.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
ok = hmac.compare_digest(expected, received)
  • Reject a timestamp older than five minutes, and treat X-EngineerIP-Delivery as a unique idempotency key.
  • Answer 2xx within 5 seconds, and only once the event is stored durably. Any other answer, or a timeout, is retried.
  • Retries back off: the next attempt waits 60 seconds after the first failure, then 30 seconds longer each time, to at most five minutes. After five failed attempts the delivery is no longer retried and is marked failed.
  • The Webhook delivery history table in the console shows attempts, the last error and the final state, so a failing endpoint is visible rather than silent.
  • Send webhooks to HTTPS endpoints wherever the network allows it.

7Event reference

Subscribe to everything with *, or list the events you handle. Every payload has an event name and a call object with the call's call_id, direction, extension, phone, caller_id_number, status, timestamps, duration_seconds, recording_status and disposition. Some events add a reason.

EventMeaning
call.startedA call was created, inbound or outbound.
call.ringingAn outbound call's first leg is ringing.
call.employee_ringingThe extension is ringing.
call.employee_answeredThe extension picked up; the customer leg is next.
call.customer_dialingWe are dialling the customer.
call.answeredThe call was answered.
call.bridgedBoth legs are connected and talking.
call.ivr_extension_selectedThe caller chose an extension from the menu. Carries digits and extension.
call.ivr_fallbackThe menu sent the caller to its fallback, for an invalid or unanswered choice.
call.voicemailThe call was handed to voicemail. reason: ivr_no_selection or inbound_not_answered.
call.missedAn inbound call went unanswered and was not sent to voicemail. reason says why.
call.recording_started · call.recording_finished · call.recording_failedRecording lifecycle for the devices that record.
call.recording_announcement_failedThe recording notice could not be played, so the call continued without it.
call.recording_deletedA recording was removed by the retention policy.
call.completedThe call ended normally, or because you asked for a hangup. reason says which.
call.failedThe call could not be completed. reason explains why.
call.dispositionYour CRM outcome and notes were saved on the call.

Use answered for reach and connect reporting, and duration_seconds for talk time. Do not derive a second duration engine in your CRM: the lifecycle events are the factual record.

8Register a device (SIP)

In Devices & SIP → Credentials you will find the values below, in one table. Each value has its own Copy button and Copy everything puts the whole set on the clipboard for the phone.

ValueWhat it looks like
SIP usernameThe account label, the extension and the number's digits, joined by underscores — for example MERIDIAN_101_13025550001. The platform generates it, keeps it unique across the whole platform, and it cannot be edited. It is the device's login identity, and a caller never dials it.
SIP passwordA generated secret with upper case, lower case, digits and symbols, rotatable from the same sheet with Change password. A linked device account's password is what actually authenticates, so rotating changes that one.
Registration server{{SIP_HOST}} — this deployment's own SIP address, with the port and transport (UDP, TCP or TLS). An administrator sets it once under Platform Settings → Server addresses, as an IP address or a subdomain whose DNS record points directly at this server — never through a web proxy, because SIP and call audio travel over UDP.
NumbersThe line the extension belongs to. It calls out with that number as caller ID, and its three digits reach it on that line.
Answers calls toThe numbers whose incoming calls ring this extension. If it says none, set the extension as a number's incoming extension under Numbers.
A device that is already registered keeps its session until it registers again: change the password on the phone after rotating it here.
Registration server, API base and webhook URLs all come from the one address in Platform Settings → Server addresses, so changing it once changes every link a customer is given.
A browser softphone needs the extension's Answers in the browser (WebRTC) option ticked, which the console shows as Browser phone. A hardware phone or desktop softphone registers on its own extension, without that option.

9Errors & limits

StatusMeaning
400Invalid JSON or phone number; an extension that is not 101–999, not yours, or ambiguous without its number; a caller_id_number that is not one of your active numbers; or an extension with no number to call out on.
401Missing, invalid, or revoked credential.
403The key lacks the scope for this endpoint.
404Unknown resource, or an endpoint that is disabled.
409Duplicate request while the first is still in flight.
429Rate limit reached — back off and retry the same idempotency key.
502 / 503The telephony engine is unavailable; the call was not placed.
  • Request bodies are limited to 64 KiB.
  • Rate limits are per client address: 120 requests a minute for the API as a whole, and 30 call starts a minute for POST /api/v1/calls.
  • Phone numbers are validated as E.164 before they reach the switch.
  • Internal engine errors are logged server-side and never echoed to clients.

10Softphone in the browser

☎
Make and take calls from a browser tab The softphone is a full SIP phone that runs in the browser. Sign in with an extension and it registers on this deployment.
Open the softphone →

Two ways to sign in

  • From the console: press Softphone on an extension's card or in its credentials sheet. A new window opens already signed in as that extension, with nothing to type.
  • By hand: open /phone and enter the extension's SIP username, SIP password and SIP domain from the Credentials sheet. The WebSocket address fills in automatically unless you change it.

Using it

  1. Dial: type or paste a number on the keypad, or press a contact. A full number reaches anyone on the platform. A three-digit extension reaches the extension on the same phone number as your line. Press the call button or Enter.
  2. In a call: mute, switch the speaker, or put the call on hold. Esc hangs up.
  3. Incoming calls: answer or decline from the same screen.
  4. Recents and contacts: the phone keeps a list of recent calls and your own contacts in this browser. With an API token in Settings, recents also load the account's call history from the server.
  5. Call quality: calls offer G.722 (HD) first, with PCMU and PCMA as fallbacks, and a badge names the codec in use. Persistent loss or jitter points at the network, not the codec.
The softphone holds your SIP password for the browser session only. It is cleared when you log out or the session ends.
The optional API token in Settings sits in the browser. Use a key that has only calls:read, and only on a device you control. Never use a key with more scopes in a browser.

The Messages tab is not connected to a messaging service yet, and says so.
