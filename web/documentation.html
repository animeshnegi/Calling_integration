1Getting started

Four steps take you from an empty account to a working integration.

  1. An administrator assigns a phone number to you. The platform creates an extension, its SIP credentials, the DID link and default call flows in one step.
  2. Open Devices & SIP, press Credentials on the extension, and enter the values into a phone or softphone.
  3. Decide how calls are answered in Call flows: the main line rings every device; a number tied to one extension rings only that extension.
  4. Create an API key in APIs & Webhooks and point a webhook endpoint at your CRM.
Programmatic accessCreate a key with the scopes your software needs, copy it once, and store it in your CRM's secret store. It is shown a single time.
Event feedbackAdd an endpoint URL, subscribe to the events you care about, and verify the signature on every delivery.

2Authentication & scopes

Every call to /api/v1/* carries a bearer credential:

# a scoped API key (preferred)
Authorization: Bearer eip_<secret>

Keys are generated with cryptographic randomness, stored only as a SHA-256 hash, list their creation time and last use, and can be revoked at any moment. A revoked key stops working immediately. Endpoints answer 401 for a missing or invalid credential and 403 when the key lacks the scope.

ScopeAllows
calls:readList, read and export calls, and read call analytics.
calls:writeStart an outbound call, hang up, or set a disposition.
config:readRead your extensions and assigned numbers.
recordings:readList recordings and stream finalized audio.
voicemail:readRead mailbox messages and their metadata.
voicemail:writeMark messages read, urgent, or delete them.
webhooks:manageCreate, edit, test and delete webhook endpoints through the API.
*Full access. Use it only for trusted administrative tooling.
A key authenticates a server. Never put it in browser JavaScript, a mobile app, or a public HTML audio element: your backend should call us and proxy what the browser needs.

3Place and track a call

POST /api/v1/calls

{
  "contact_id": "582",
  "member_id": "37",
  "extension": "101",
  "phone": "+16235551234",
  "caller_id_number": "+13025550101"
}

phone must be in E.164 form. extension is one of your active extensions and defaults to the customer's default outbound extension. caller_id_number is optional, and when supplied must be a number assigned to that extension; otherwise the extension's default number is used.

The call is employee-first: the extension rings, and only when it answers does the platform dial the customer and bridge the two legs. No answer means the customer is never called.

Send a unique Idempotency-Key header (8–128 safe characters) for every user click or job. A replay of a completed request returns the original call with "idempotent_replay": true; a duplicate that is still in flight returns 409. This is what stops a network retry from placing a second paid call.

# start a call and keep the identifier
curl -sS -X POST https://<your-host>/api/v1/calls \\
  -H "Authorization: Bearer $EIP_KEY" \\
  -H "Content-Type: application/json" \\
  -H "Idempotency-Key: $(uuidgen)" \\
  -d '{"phone":"+16235551234","extension":"101"}'

Following one call

EndpointPurpose
GET /api/v1/calls/<call_id>Current state of one call.
GET /api/v1/callsSearch and page through call history.

Treat call_id as the stable identifier and make your own processing idempotent on it.

4Read your own configuration

GET /api/v1/extensionsActive extension numbers and the default outbound extension.

5Recordings & voicemail

Recording is decided per device: an extension records while its own switch is on, in Extensions → Edit. There is no global policy to fight with.

EndpointPurpose
GET /api/v1/recordingsCalls that have recording metadata.
GET /api/v1/recordings/<call_id>/fileStreams a finalized recording. Supports Range requests for seeking.
GET /api/v1/voicemailsMessages grouped by extension.
POST /api/v1/voicemails/<id>/readMark a message read or urgent, or delete it.

A recording is only available once its status is finalized; anything else answers 404. Proxy audio through your backend so the key never reaches a browser.

6Webhooks & signatures

Add an endpoint in APIs & Webhooks → Add endpoint with the secret your service expects. Every delivery carries the secret as a bearer token and as an HMAC signature of the exact bytes sent: 

POST /your-endpoint HTTP/1.1
Authorization: Bearer <your webhook secret>
X-EngineerIP-Delivery: 8f1c…-unique-id
X-EngineerIP-Timestamp: 1758554400
X-EngineerIP-Signature: sha256=<hex>

{"event":"call.completed","data":{ … }}

Verify it like this — the raw body, before any JSON parsing:

// Node
const expected = crypto
  .createHmac('sha256', secret)
  .update(timestamp + '.' + rawBody)
  .digest('hex');
const ok = crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(signature));

# Python
expected = hmac.new(secret.encode(), f"{timestamp}.".encode() + raw_body, hashlib.sha256).hexdigest()
ok = hmac.compare_digest(expected, signature)
  • Reject a timestamp older than five minutes, and treat X-EngineerIP-Delivery as a unique idempotency key.
  • Answer 2xx only once the event is stored durably; anything else is retried from the delivery outbox.
  • The delivery history table in the console shows attempts, the last error and the terminal state, so a failing endpoint is visible rather than silent.
  • Use HTTPS outside a private network and allowlist our source address where your platform supports it.

7Event reference

Subscribe to everything with *, or list the events you handle. Each payload contains the call object shown in Webhook delivery history: call_id, direction, extension, phone, caller ID, status, timestamps, duration and recording state.

EventMeaning
call.startedA call was created, inbound or outbound.
call.employee_ringingThe extension is ringing.
call.employee_answeredThe extension picked up; the customer leg is next.
call.customer_dialingWe are dialling the customer.
call.bridged / call.answeredBoth legs are connected and talking.
call.recording_started · call.recording_finished · call.recording_failedRecording lifecycle for the devices that record.
call.completedThe call ended; the payload carries the final duration and status.
call.failedThe call could not be completed; the payload explains why.
call.hangup_requested · call.dispositionYour own hangup or outcome, echoed back as state.

Use answered for reach/connect reporting and duration_seconds for talk time. Do not derive a second duration engine in your CRM: the lifecycle events are the factual record.

8Register a device (SIP)

In Devices & SIP → Credentials you will find the values below. The sheet can copy them one by one or as a single block for the phone.

ValueWhat it looks like
SIP usernameSix random letters, an underscore and the extension — for example QwErTy_101. The platform generates it, keeps it unique across the whole platform, and it cannot be edited: it is the device's identity.
SIP passwordA generated secret, rotatable from the same sheet. A linked device account's password is what actually authenticates, so rotating changes that one.
Registration serverThe carrier or platform SIP host, with port and transport (UDP, TCP or TLS).
NumberThe DID the extension answers, so you can confirm the right line rings.
A device that is already registered keeps its session until it registers again: change the password on the phone after rotating it here.

9Errors & limits

StatusMeaning
400Invalid JSON, phone number, extension, or disposition data.
401Missing, invalid, or revoked credential.
403The key lacks the scope for this endpoint.
404Unknown resource, or an endpoint that is disabled.
409Duplicate request while the first is still in flight.
429Rate limit reached — back off and retry the same idempotency key.
502 / 503The telephony engine is unavailable; the call was not placed.
  • Request bodies are limited to 64 KiB.
  • Request limits are enforced per client: a general authenticated limit, and a stricter one for starting calls.
  • Phone numbers are validated as E.164 before they reach the switch.
  • Internal engine errors are logged server-side and never echoed to clients.
